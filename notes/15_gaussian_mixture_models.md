# GAUSSIAN MIXTURE MODELS

## 1. Overview in Latency Decomposition Context

This note covers the theory behind Gaussian Mixture Models (GMMs), the unsupervised clustering method designated in the project roadmap (`README.md`, Phase 4) for the final analytical stage of this research: taking the isolated Stage 2 residuals ($D_{\text{queue}}$) and mathematically separating them into distinct **latent routing/congestion states**, in order to compare the Singapore and India network environments.

The core motivating question this method answers: once we have a large collection of residual queuing delay values, is that collection best described as **one single population** with one central tendency and spread, or is it actually a **mixture of several distinct underlying populations** — for example, "the empty-buffer state," "the moderate-load state," and "the bufferbloat state" described in `06_tcp_protocol.md`, Section 3 (Multimodal Distributions) — that happen to be blended together in the raw data? GMMs provide a rigorous, probabilistic way to answer this question and to recover the individual populations.

---

## 2. Why a Single Gaussian Distribution Is Insufficient

### 2.1 The Naive Assumption

The simplest possible model for a collection of residual values $\{r_1, r_2, \dots, r_n\}$ is to assume they are all drawn from **one** Normal (Gaussian) distribution:

$$
r_i \sim \mathcal{N}(\mu, \sigma^2)
$$

Where $\mu$ is the mean and $\sigma^2$ is the variance, both estimated from the data (e.g., via sample mean and sample variance).

### 2.2 Why This Assumption Fails for Queuing Delay Residuals

Per `06_tcp_protocol.md`, Section 3 ("Multimodal Distributions (GMM Relevance)"), TCP's congestion behavior naturally produces **at least two distinct operational regimes**:

1. **The Fast/Empty Path Mode**: low congestion window, zero queue occupancy, residuals clustered tightly near zero.
2. **The Congestion/Bufferbloat Mode**: maximum congestion window, saturated buffers, residuals clustered around a much higher, inflated value.

A dataset generated by switching between these two regimes over time does not look like a single bell curve. It looks like **two separate bumps** — a **bimodal** (or, more generally, **multimodal**) distribution. Fitting a single Gaussian to genuinely multimodal data produces a fitted curve that sits awkwardly in between the two true modes, fitting neither well, and — critically — the single fitted mean $\hat\mu$ does not correspond to any real, physically meaningful operating state of the network. It is a statistical artifact of averaging across two distinct realities, not a description of either one.

**This is the precise mathematical justification for needing a mixture model**: the data-generating process itself is not one Gaussian — it is a probabilistic combination of several Gaussians, each corresponding to a genuine, physically distinct network state, and the model must be structured to reflect that.

---

## 3. The Mathematical Definition of a Gaussian Mixture Model

### 3.1 The Generative Story

A GMM assumes the data was generated by the following two-step random process, for each observation $i$:

1. **First**, randomly select one of $K$ underlying "component" distributions, according to a fixed set of mixing probabilities $\{\pi_1, \pi_2, \dots, \pi_K\}$ (where $\sum_{k=1}^{K} \pi_k = 1$ and each $\pi_k \geq 0$).
2. **Then**, draw the observed value $r_i$ from that selected component's own Gaussian distribution, $\mathcal{N}(\mu_k, \sigma_k^2)$.

Crucially, we **never observe which component generated any given point** — this hidden, unobserved choice is called a **latent variable**. This is precisely what makes GMM an *unsupervised* method: there are no labels telling us "this observation came from the bufferbloat state." The entire task is to infer both the component parameters and the most likely hidden assignment, from the observed data alone.

### 3.2 The Probability Density Function

The overall probability density of observing a value $r$ under a $K$-component GMM is the **weighted sum** of the individual Gaussian component densities:

$$
p(r) = \sum_{k=1}^{K} \pi_k \cdot \mathcal{N}(r \mid \mu_k, \sigma_k^2)
$$

Where each individual Gaussian component's density function is the standard Normal PDF:

$$
\mathcal{N}(r \mid \mu_k, \sigma_k^2) = \frac{1}{\sqrt{2\pi\sigma_k^2}} \exp\left(-\frac{(r - \mu_k)^2}{2\sigma_k^2}\right)
$$

Where, for each component $k \in \{1, \dots, K\}$:

- $\pi_k$ → the **mixing weight**, representing the overall proportion of the dataset that belongs to component $k$ (e.g., "60% of all probes occur during the empty-queue state, 40% during the bufferbloat state" → $\pi_1 = 0.6, \pi_2 = 0.4$)
- $\mu_k$ → the mean residual delay of component $k$ (e.g., the empty-queue state might have $\mu_1 \approx 0$ ms, the bufferbloat state might have $\mu_2 \approx 45$ ms)
- $\sigma_k^2$ → the variance of component $k$ (how spread out the residuals are *within* that state — even the "bufferbloat" state will have some jitter around its own typical elevated value)

### 3.3 Multivariate Generalization

If clustering is performed not just on the scalar residual value but on a **feature vector** (e.g., residual delay jointly with a passive-capture traffic-volume metric, which is a natural extension for this project's richer feature set), each component becomes a **multivariate** Gaussian:

$$
\mathcal{N}(\mathbf{r} \mid \boldsymbol{\mu}_k, \boldsymbol{\Sigma}_k) = \frac{1}{(2\pi)^{d/2} |\boldsymbol{\Sigma}_k|^{1/2}} \exp\left(-\frac{1}{2}(\mathbf{r} - \boldsymbol{\mu}_k)^T \boldsymbol{\Sigma}_k^{-1} (\mathbf{r} - \boldsymbol{\mu}_k)\right)
$$

Where:

- $\mathbf{r}$ → a $d$-dimensional feature vector for one observation (e.g., $[\text{residual\_delay}, \text{traffic\_volume}]$, so $d=2$)
- $\boldsymbol{\mu}_k$ → the $d$-dimensional mean vector of component $k$
- $\boldsymbol{\Sigma}_k$ → the $d \times d$ **covariance matrix** of component $k$, which captures not only each feature's individual variance but also how features co-vary with each other within that component (e.g., "in the bufferbloat state, higher traffic volume is strongly correlated with higher residual delay")
- $|\boldsymbol{\Sigma}_k|$ → the determinant of the covariance matrix

This generalization is directly relevant to the project's Phase 4 goal, since routing-state separation is likely to be cleaner when using multiple correlated features jointly (e.g., residual delay + concurrent traffic volume + protocol flag) rather than residual delay alone.

## 4. Parameter Estimation: The Expectation-Maximization (EM) Algorithm

### 4.1 Why Simple Estimation Doesn't Work Here

For a single Gaussian, estimating $\mu$ and $\sigma^2$ is trivial (sample mean and sample variance, closed-form). For a GMM, this is not possible directly, because the component membership of each point (which Gaussian it came from) is an unobserved latent variable — we cannot simply compute "the mean of Cluster 1's points" because we do not yet know which points belong to Cluster 1. This is a **chicken-and-egg problem**: if we knew the cluster assignments, estimating each component's parameters would be easy; and if we knew each component's parameters, computing the most likely cluster assignment for each point would be easy. But we start out knowing neither.

The **Expectation-Maximization (EM) algorithm** solves this by iteratively alternating between the two halves of this problem, each time using the current best guess of one to improve the other, provably converging to a good solution.

### 4.2 Step 0 — Initialization

Choose an initial guess for the number of components $K$ (see Section 5 for how $K$ itself is chosen) and initialize each component's parameters ($\pi_k$, $\mu_k$, $\sigma_k^2$ or $\boldsymbol{\Sigma}_k$) — commonly via random initialization or via a faster clustering heuristic like K-means used only to seed the starting point.

### 4.3 Step 1 — The Expectation (E) Step

Given the **current** parameter estimates, compute, for every data point $r_i$ and every component $k$, the **posterior probability** that point $i$ was generated by component $k$ — this quantity is called the **responsibility**, denoted $\gamma_{ik}$:

$$
\gamma_{ik} = \frac{\pi_k \cdot \mathcal{N}(r_i \mid \mu_k, \sigma_k^2)}{\sum_{j=1}^{K} \pi_j \cdot \mathcal{N}(r_i \mid \mu_j, \sigma_j^2)}
$$

This is a direct application of **Bayes' theorem**: it converts the "prior" probability of belonging to component $k$ ($\pi_k$) combined with "how likely component $k$'s distribution is to have produced this specific observed value" (the Gaussian density term) into an updated, "posterior" probability that specific point $i$ actually belongs to component $k$, given what we've observed.

Note that $\gamma_{ik}$ is a **soft assignment** — a number between 0 and 1, not a hard "yes/no" cluster label. A given probe's residual value might be assigned $\gamma_{i,\text{empty}} = 0.7$ and $\gamma_{i,\text{bufferbloat}} = 0.3$, reflecting genuine ambiguity about which state produced it (this soft-assignment property is precisely what distinguishes GMM from a harder clustering method like K-means — see Section 6).

### 4.4 Step 2 — The Maximization (M) Step

Given the responsibilities $\gamma_{ik}$ computed in the E-step, **re-estimate** each component's parameters, weighting every data point's contribution to each component's statistics by that point's responsibility for that component:

**Updated mixing weight:**
$$
\pi_k^{\text{new}} = \frac{1}{n}\sum_{i=1}^{n} \gamma_{ik}
$$

**Updated mean:**
$$
\mu_k^{\text{new}} = \frac{\sum_{i=1}^{n} \gamma_{ik} \cdot r_i}{\sum_{i=1}^{n} \gamma_{ik}}
$$

**Updated variance:**
$$
{\sigma_k^2}^{\text{new}} = \frac{\sum_{i=1}^{n} \gamma_{ik} \cdot (r_i - \mu_k^{\text{new}})^2}{\sum_{i=1}^{n} \gamma_{ik}}
$$

These formulas are the natural, intuitive generalizations of ordinary sample mean/variance formulas, except every point's contribution is weighted by how strongly it is believed (per the current E-step) to belong to that specific component, rather than every point counting equally toward every component.

### 4.5 Step 3 — Iterate to Convergence

Steps 4.3 and 4.4 (E-step, M-step) are repeated, alternately, using each step's output as the input to the next. Each full E-M cycle is **mathematically guaranteed to never decrease** the overall data likelihood (this guarantee is a well-established theoretical property of the EM algorithm and does not need to be independently re-derived here) — meaning the model's fit to the data monotonically improves (or plateaus) with every iteration. The algorithm is stopped once the change in total log-likelihood (or the change in parameter values) between successive iterations falls below a small threshold, indicating **convergence**.

### 4.6 Important Caveat: Local Optima

EM is only guaranteed to converge to a **local** optimum, not necessarily the single best possible (**global**) solution. Because the algorithm's final result depends on its random starting initialization (Section 4.2), **different random initializations can converge to different final clusterings**. The standard mitigation, used by default in most implementations (including scikit-learn's `GaussianMixture`), is to **run the entire EM procedure multiple times from different random initializations** and keep the run that achieves the highest final log-likelihood. This should not be treated as an optional refinement — it is a standard, necessary part of correctly using GMM, and any implementation for this project should explicitly set the relevant parameter (e.g., scikit-learn's `n_init`, with a value of at least 10) rather than relying on a single run.

## 5. Choosing the Number of Components ($K$)

### 5.1 Why This Cannot Be Guessed Arbitrarily

The number of underlying congestion "states" is not something we necessarily know in advance — while `06_tcp_protocol.md` describes two conceptual states (empty-path vs. bufferbloat), the true number of statistically distinguishable states in real collected data could plausibly be more (e.g., a distinct "moderate congestion" state, or separate states per major routing path), or the two conceptual states might not even be statistically separable given measurement noise. $K$ must be determined empirically from the data itself, not assumed.

### 5.2 The Overfitting Risk of Naively Maximizing Likelihood

It might seem natural to simply try several values of $K$ and pick whichever one produces the highest data likelihood. This fails, for the same fundamental reason that a decision tree with unlimited depth overfits (per `11_xgboost_fundamentals.md`, Section 2.2): a GMM with more components has strictly more free parameters, and can therefore always fit the *training* data at least as well as a GMM with fewer components — in the extreme case, a GMM with $K = n$ (one component per data point) achieves a perfect but completely meaningless fit, memorizing every individual noisy observation as its own "state." Likelihood alone, unpenalized, will always favor more components and must not be used in isolation to choose $K$.

### 5.3 The Correct Approach: Information Criteria

The standard solution is to use a metric that explicitly balances model fit against model complexity, analogous in spirit to the $\Omega(f_t)$ complexity penalty used in XGBoost's own objective function (`11_xgboost_fundamentals.md`, Section 4.5). The two most common such metrics are:

**Akaike Information Criterion (AIC):**
$$
\text{AIC} = 2p - 2\ln(\hat{L})
$$

**Bayesian Information Criterion (BIC):**
$$
\text{BIC} = p\ln(n) - 2\ln(\hat{L})
$$

Where:

- $p$ → the total number of free parameters in the model (for a GMM with $K$ univariate components: $p = K$ mixing weights $+ K$ means $+ K$ variances, minus 1 because the mixing weights are constrained to sum to 1)
- $\hat{L}$ → the maximized data likelihood achieved by the fitted model (the quantity EM optimizes, per Section 4.5)
- $n$ → the number of observations in the dataset

Both formulas share the same essential structure: a penalty term that grows with model complexity ($2p$ for AIC, $p\ln(n)$ for BIC — note BIC penalizes complexity more heavily as sample size $n$ grows) minus a reward term for how well the model fits the data ($-2\ln(\hat L)$; a higher likelihood makes this term more negative, i.e., lowers the overall criterion, since lower AIC/BIC is better).

**Procedure:** fit a separate GMM for a range of candidate $K$ values (e.g., $K = 1, 2, 3, \dots, 8$), compute AIC and/or BIC for each fitted model, and select the $K$ that **minimizes** the chosen criterion. Plotting AIC/BIC against $K$ typically produces an "elbow" — a point where increasing $K$ further yields only marginal further improvement — and the value at or near this elbow is the appropriate choice.

**Recommendation for this project:** prefer BIC over AIC when the dataset is large (BIC's stronger complexity penalty for large $n$ helps avoid selecting spuriously many components purely because a large sample size makes small likelihood improvements statistically "detectable" but not practically meaningful) — and given the project's multi-week continuous data collection design (`README.md` roadmap), the dataset size is expected to be large enough that this consideration applies.

## 6. GMM vs. K-Means: Why GMM Is the Correct Choice Here (Not Just a More Complex Alternative)

It is worth being explicit about why this project's roadmap specifies GMM rather than the simpler and more commonly known K-means clustering algorithm, since the choice has concrete mathematical justification, not just stylistic preference.

| Property | K-Means | Gaussian Mixture Model |
| :--- | :--- | :--- |
| **Assignment type** | Hard assignment — every point belongs to exactly one cluster | Soft assignment — every point gets a probability of belonging to each cluster (Section 4.3) |
| **Cluster shape assumption** | Implicitly assumes clusters are spherical and roughly equal in size/spread (it minimizes Euclidean distance to a cluster center) | Explicitly models each cluster's own individual variance (or full covariance matrix in the multivariate case), allowing clusters of different shapes and sizes |
| **Underlying statistical model** | None — it is a purely geometric/distance-based heuristic algorithm with no explicit probability distribution | A fully specified probabilistic generative model (Section 3.1), enabling principled statistical comparisons (e.g., via AIC/BIC, Section 5.3) |

**Why the soft-assignment property matters specifically for this project:** a residual queuing delay value sitting in the ambiguous zone between the "empty path" state and the "moderate congestion" state is a genuinely uncertain case — it is not obviously and unambiguously one or the other. Per `04_queuing_delay.md`'s description of traffic burstiness ("even if average traffic intensity is low, traffic often arrives in dense micro-bursts"), the boundary between operational states is expected to be genuinely fuzzy, not sharply delineated. GMM's soft, probabilistic assignment directly and honestly represents this ambiguity; K-means' hard assignment would force every borderline point into one arbitrary bucket or the other, discarding real uncertainty as if it did not exist.

**Why the flexible-covariance property matters specifically for this project:** per `06_tcp_protocol.md`, Section 3, the "empty path" state is described as having minimal variance (tightly clustered near a minimum RTT envelope), while the "bufferbloat" state is inherently more volatile (driven by traffic burstiness). K-means' implicit assumption of roughly equal-sized, spherical clusters is directly violated by this expected asymmetry between states — GMM's per-component variance/covariance parameters ($\sigma_k^2$ or $\boldsymbol\Sigma_k$) are specifically designed to capture exactly this kind of state-dependent spread.

## 7. Applying GMM to This Project's Specific Goal: Cross-Country State Comparison

### 7.1 The Analytical Procedure

Per the roadmap (`README.md`, Phase 4), the intended analysis is:

1. Fit a GMM independently to the collected residual dataset for **Singapore**, selecting $K$ via BIC (Section 5.3).
2. Fit a **separate** GMM independently to the residual dataset for **India**, again selecting its own (possibly different) $K$ via BIC.
3. Compare the resulting fitted parameters ($\hat\pi_k$, $\hat\mu_k$, $\hat\sigma_k^2$ for each recovered component) **across the two countries** to characterize how each network environment's congestion behavior differs structurally, not just in aggregate average delay.

**Note on why two separate models are fit rather than one combined model:** fitting entirely separate GMMs (rather than fitting one shared GMM across the pooled dataset with a "country" feature included) directly follows from `09_protocol_comparison.md`'s own stated hypothesis, Section 4 — that Singapore and India are expected to exhibit *structurally different* patterns (Singapore: Stage 1 baselines converge tightly, most variance sits in Stage 2; India: Stage 1 baselines diverge by protocol due to multi-hop routing). Fitting independent GMMs allows the number of recovered states ($K$), and not just their locations, to differ freely between the two countries, which is essential if the underlying congestion structures are genuinely different in kind, not just in degree.

### 7.2 Interpreting the Comparison

Once both GMMs are fit, concrete, well-defined comparisons become possible:

- **Comparing $K$ itself**: if Singapore's optimal $K$ (via BIC) is smaller than India's, this is direct statistical evidence that Singapore's network exhibits fewer distinct operational regimes — consistent with the hypothesis in `10_quantile_regression_envelope.md`, Section 5, that Singapore's environment is "high density & minimal variance" while India's is "highly volatile & multimodal."
- **Comparing component means ($\hat\mu_k$)**: the specific delay values at which each country's distinct states center reveal the magnitude of typical congestion events in each environment.
- **Comparing mixing weights ($\hat\pi_k$)**: the proportion of time each country's network spends in each state (e.g., "India spends 30% of probes in a high-congestion state vs. Singapore's 8%") is a direct, interpretable, quantitative claim suitable for the project's eventual research write-up (`README.md`, Phase 4).
- **Comparing component variances ($\hat\sigma_k^2$)**: reveals whether a given operational state (e.g., "bufferbloat") is more or less *consistent* in one country vs. the other — a high-variance bufferbloat state suggests more erratic, harder-to-predict congestion behavior than a low-variance one, even if the two have similar mean delay.

### 7.3 A Necessary Precondition: This Analysis Assumes Residual Validity

This entire GMM-based analysis is performed on **Stage 2 residuals**, not raw RTT. This means the validity of every conclusion drawn in Section 7.2 is entirely dependent on the residual having been correctly and validly constructed in the first place, per the full chain of reasoning established in `12_residual_learning_theory.md`. If Stage 1 carries an uncorrected bias (per `12_residual_learning_theory.md`, Section 4), that bias will manifest as a **spurious shift in the GMM's recovered component means**, and could easily be misinterpreted as a genuine cross-country difference in congestion behavior when it is actually nothing more than an artifact of differing Stage 1 fit quality between the two countries' datasets. **Before trusting any cross-country GMM comparison, the Section 6 diagnostic checks from `12_residual_learning_theory.md` must have already been run and passed independently for both the Singapore and India datasets.**

## 8. Practical Implementation Notes (scikit-learn)

```python
from sklearn.mixture import GaussianMixture
import numpy as np

def fit_best_gmm(residuals: np.ndarray, k_range=range(1, 9), n_init: int = 10, random_state: int = 42):
    """
    Fits a GaussianMixture model for each K in k_range, selects the
    best K by minimum BIC, and returns the best-fitted model along
    with the BIC scores for all candidates (for inspection/plotting).

    `residuals` should be a 2D array of shape (n_samples, n_features) --
    reshape a 1D residual array with `.reshape(-1, 1)` if clustering
    on residual delay alone.
    """
    bic_scores = {}
    fitted_models = {}

    for k in k_range:
        gmm = GaussianMixture(
            n_components=k,
            n_init=n_init,          # mitigates the local-optima risk, Section 4.6
            random_state=random_state,
            covariance_type="full", # allows each component its own full covariance shape
        )
        gmm.fit(residuals)
        bic_scores[k] = gmm.bic(residuals)
        fitted_models[k] = gmm

    best_k = min(bic_scores, key=bic_scores.get)
    return fitted_models[best_k], best_k, bic_scores
```

**Note on `covariance_type`**: scikit-learn's `GaussianMixture` supports several covariance structure options (`full`, `tied`, `diag`, `spherical`), trading off flexibility against the number of free parameters (and therefore overfitting risk, per Section 5.2). `full` (a completely unconstrained covariance matrix per component) is the most flexible and is a reasonable default starting point given this project's expectation of asymmetric, differently-shaped states (Section 6) — but if the multivariate feature set (Section 3.3) grows large relative to the available sample size, a more constrained option (e.g., `diag`, which assumes features are uncorrelated within a component) may be necessary to avoid an unstable or poorly-conditioned covariance estimate, and should be checked via the same BIC comparison procedure described in Section 5.3 (BIC's parameter-count term $p$ differs by `covariance_type`, so BIC can be used to compare across covariance structures as well as across $K$).

## 9. Diagnostic Checks Before Trusting GMM Results

1. **Convergence check**: confirm the fitted model's `converged_` attribute (scikit-learn) is `True`, and inspect that the log-likelihood trace across EM iterations (Section 4.5) is monotonically non-decreasing and has genuinely plateaued, not merely hit an iteration limit.
2. **Multiple-restart stability check**: re-run the full fitting procedure (Section 4.6) with several different `random_state` seeds and confirm the recovered cluster means/weights are consistent across runs. Substantial disagreement between runs indicates the likelihood surface has multiple competing local optima and the result should not yet be trusted as stable.
3. **BIC elbow inspection**: visually plot BIC vs. $K$ (Section 5.3) rather than blindly trusting the single numerical minimum — a genuinely ambiguous or flat BIC curve across several $K$ values indicates the data does not strongly support any particular number of states, and this ambiguity should be reported honestly rather than resolved by picking an arbitrary "winning" $K$.
4. **Physical plausibility check**: verify that the recovered component means ($\hat\mu_k$) are physically sensible given the known bounds established elsewhere in this project's notes — for example, per Section 5.1 of `04_queuing_delay.md`, no legitimate component mean should be negative (since $D_{\text{queue}} \geq 0$ by physical definition), and a component mean or variance wildly outside plausible network delay ranges is a strong signal of a residual-construction problem (Section 7.3), not a genuine discovered network state.

## 10. Summary: The Precise Chain of Reasoning

1. Queuing delay residuals are expected to be genuinely multimodal — generated by switching between distinct operational network states (empty-path, moderate load, bufferbloat) — not by a single smooth distribution, per `06_tcp_protocol.md`'s own stated hypothesis (Section 2).
2. A Gaussian Mixture Model formalizes this as a probabilistic combination of $K$ individual Gaussian components, each with its own mixing weight, mean, and variance/covariance, with component membership treated as an unobserved latent variable (Section 3).
3. Because component membership is unobserved, parameters are estimated using the iterative Expectation-Maximization algorithm, which alternates between computing soft probabilistic cluster assignments (E-step) and updating each component's parameters using those assignments as weights (M-step), provably improving fit at every iteration (Section 4).
4. EM converges only to a local optimum, so multiple random restarts are a mandatory part of correct usage, not an optional refinement (Section 4.6).
5. The number of components $K$ cannot be chosen by likelihood alone — a complexity-penalized criterion (BIC, preferred over AIC for this project's expected large sample size) must be used to prevent selecting an overfit, memorized clustering (Section 5).
6. GMM is specifically preferred over K-means for this project because of two properties directly justified by this project's own prior notes: soft assignment honestly represents genuine ambiguity near state boundaries (motivated by traffic burstiness, `04_queuing_delay.md`), and flexible per-component variance correctly captures the expected asymmetry between low-variance and high-variance operational states (`06_tcp_protocol.md`) (Section 6).
7. The project's Phase 4 goal is served by fitting entirely separate GMMs for Singapore and India (rather than one pooled model), enabling comparison not just of delay magnitude but of the number, weight, and consistency of each country's distinct congestion states (Section 7).
8. This entire analysis is only valid to the extent that the underlying residuals were correctly constructed per `12_residual_learning_theory.md` — a Stage 1 bias will surface as a spurious, misleading shift in GMM results rather than a genuine cross-country finding, so residual validity must be confirmed first (Section 7.3).
9. A concrete set of diagnostic checks (Section 9) — convergence, restart stability, BIC elbow shape, and physical plausibility of recovered parameters — should be run against real fitted models before any cross-country conclusion is reported.
